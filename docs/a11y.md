# Accessibility

Target: WCAG 2.2 AA across every marketing route.

## Structural

- `<html lang="en">` set at [app/layout.tsx](../app/layout.tsx).
- One `<h1>` per page (Hero on the home page; page title elsewhere).
- Landmark set on every route: `<header>`, `<nav aria-label="Primary">`, `<main id="main" tabIndex="-1">`, `<footer>`. Site layout at [app/(site)/layout.tsx](<../app/(site)/layout.tsx>).
- Skip-link ([components/layout/SkipLink.tsx](../components/layout/SkipLink.tsx)) is the first focusable element on every page and jumps to `#main`.

## Keyboard

- Every interactive element receives a `:focus-visible` ring in `--color-focus`, applied globally at [app/globals.css](../app/globals.css).
- Mobile navigation uses the native `<dialog>` element via `.showModal()` — the browser handles focus trap, ESC-to-close, initial focus, and inert siblings ([components/layout/MobileNav.tsx](../components/layout/MobileNav.tsx)).
- The 3D scene has no interactive controls; keyboard focus never enters the canvas.

## Colour and contrast

- Palette tokens in [app/globals.css](../app/globals.css) meet AA against both dark and light backgrounds:
  - `--color-text` on `--color-bg`: 13.6:1 (dark), 16.7:1 (light).
  - `--color-text-muted` on `--color-bg`: 5.4:1 (dark), 6.9:1 (light).
  - `--color-primary` on `--color-bg`: 7.1:1 (dark), 6.2:1 (light) — passes AA large & regular.
- Focus ring is 2px solid `--color-focus` with 2px offset — meets non-text contrast requirement.

## Motion

- `prefers-reduced-motion: reduce` is honored globally in [app/globals.css](../app/globals.css) (animations/transitions collapsed to 0.01ms, smooth scroll disabled).
- Lenis smooth-scroll skips both reduced-motion and iOS Safari ([components/scroll/LenisProvider.tsx](../components/scroll/LenisProvider.tsx)).
- The Three.js hero scene is gated on `prefers-reduced-motion`, IntersectionObserver visibility, `requestIdleCallback`, and a WebGL capability check ([components/three/hooks/useSceneMountGate.ts](../components/three/hooks/useSceneMountGate.ts)). If any gate fails, the static text hero renders instead.

## Forms

- Every input has a visible `<label>` associated by `htmlFor` / `id`.
- Errors use `role="alert"` inline ([components/ui/FieldError.tsx](../components/ui/FieldError.tsx)) and are linked back to inputs via `aria-describedby` + `aria-invalid`.
- On submit-with-errors, [components/forms/ContactForm.tsx](../components/forms/ContactForm.tsx) renders an **error summary** at the top with `role="alert"` and focus lands on it — each entry is a link that jumps focus to the offending field.
- The honeypot input is `sr-only` + `aria-hidden` + `tabIndex={-1}` so keyboard and screen-reader users never encounter it.
- Server responses funnel into a `<div aria-live="assertive">` region below the submit button.

## Route changes

- App Router ships its own `<title>` announcer for SPA navigations. We back it up with [components/a11y/RouteAnnouncer.tsx](../components/a11y/RouteAnnouncer.tsx) — a polite live region that speaks the new document title 100ms after every path change, in case async metadata hasn't resolved yet.

## Images

- All decorative images use `alt=""`. Content images have descriptive alt text.
- The hero brand logo is decorative (adjacent brand text carries the meaning), so `alt=""`.

## Tooling

- Storybook-free — the `/design` route is the QA surface. Axe DevTools should return zero violations on `/`, `/blogs`, `/blogs/[slug]`, `/newsletter`, `/newsletter/[slug]`, `/contact`, `/design`.
- Playwright + `@axe-core/playwright` integration lands in stage 13 to enforce this in CI.
