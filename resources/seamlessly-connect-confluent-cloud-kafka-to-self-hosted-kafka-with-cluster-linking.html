Seamlessly Connect Confluent Cloud Kafka to Self-Hosted Kafka with Cluster Linking

Published on Medium · Jun 26, 2025

Read the complete step-by-step configuration on Medium.

Read on Medium →

Hybrid architectures that mix on-premise infrastructure with cloud-native services are increasingly the norm, and Kafka is no exception. This article covers connecting Confluent Cloud Kafka to a self-hosted Kafka cluster using Cluster Linking, so topics stay in sync across environments without bolting on a separate replication tool.

What Cluster Linking does

Cluster Linking is a Confluent Cloud feature that replicates topics and partitions directly between clusters — cloud-to-cloud, cloud-to-on-prem, or across regions — without the operational overhead of running something like MirrorMaker 2. It's built for exactly this kind of hybrid, multi-region setup.

Why teams replicate across environments

  • Disaster recovery: if one cluster goes down, the other keeps serving reads and writes.
  • Global data distribution: replicate topics closer to where they're consumed for lower latency.
  • Hybrid cloud architecture: keep on-prem and cloud Kafka in sync as a deliberate long-term architecture, not just a migration step.
  • Data migration: move from on-prem to Confluent Cloud with zero downtime during the cutover.

The full Medium post walks through the cluster setup on both sides, enabling the link, and verifying replication end to end — that detail is worth reading directly at the source link above.
